# EdTech CRM & Inquiry System

Initial project scaffold for a React/Vite frontend and an Express API. This setup does not implement inquiry handling, admin authentication, dashboard views, filtering, or database queries yet.

## Requirements mapped to the planned structure

- Public inquiry form and protected admin dashboard: `frontend/src/`
- Admin login and custom JWT authentication: `backend/src/` using `jsonwebtoken` and `bcrypt` (Supabase Auth will not be used)
- Inquiry table, category/user-type filters, and name/phone search: frontend views backed by API routes
- Supabase PostgreSQL: `pg` connection configuration and database access under `backend/src/` (to be implemented next)
- Inquiry status: database and API fields displayed in the admin inquiry table

## Structure

```text
|-- README.md                  # Project overview, structure, and setup instructions
|-- backend/
|   |-- .env.example           # Names of local backend environment variables; contains placeholders only
|   |-- package.json            # Backend dependencies and npm scripts
|   |-- package-lock.json       # Exact backend dependency versions
|   |-- node_modules/           # Installed backend packages (generated, not committed)
|   `-- src/
|       |-- app.js              # Express middleware and setup health endpoint
|       `-- server.js           # Loads environment settings and starts the HTTP server
`-- frontend/
    |-- .gitignore              # Vite template ignore rules
    |-- .oxlintrc.json           # Oxlint configuration generated by Vite
    |-- index.html               # Vite HTML entry point
    |-- package.json             # React/Vite dependencies and frontend scripts
    |-- package-lock.json        # Exact frontend dependency versions
    |-- README.md                # Vite-generated frontend starter documentation
    |-- vite.config.js           # Vite and React plugin configuration
    |-- node_modules/            # Installed frontend packages (generated, not committed)
    |-- public/
    |   |-- favicon.svg          # Starter favicon
    |   `-- icons.svg             # Starter icon sprite
    `-- src/
        |-- App.css              # Starter app-level styles
        |-- App.jsx              # Starter React screen; replace with CRM views later
        |-- index.css             # Global starter styles
        |-- main.jsx              # React browser entry point
        `-- assets/
            |-- hero.png          # Vite starter artwork
            |-- react.svg         # React starter logo
            `-- vite.svg          # Vite starter logo
```

`frontend/vite.config.js` configures Vite and its React plugin. The generated `frontend/README.md` is Vite-specific starter documentation.
## Initialize from an empty workspace

Run these commands from the project root in PowerShell. The Vite flags prevent an interactive prompt and avoid starting a dev server during scaffolding.

```powershell
npx --yes create-vite@latest frontend -- --template react --no-interactive --no-immediate
Push-Location frontend
npm install
Pop-Location

New-Item -ItemType Directory -Force backend\src | Out-Null
Push-Location backend
npm init -y
npm install express pg jsonwebtoken bcrypt dotenv cors
npm install --save-dev nodemon
npm pkg set "scripts.dev=nodemon src/server.js" "scripts.start=node src/server.js"
Pop-Location
```

The Vite-generated `frontend/README.md` is starter documentation; `frontend/vite.config.js` configures Vite and its React plugin.

## Run locally

Prerequisites: Node.js and npm.

```powershell
# Frontend terminal
cd frontend
npm run dev

# Backend terminal
cd backend
Copy-Item .env.example .env
npm run dev
```

The frontend is served at `http://localhost:5173`; the API listens on `http://localhost:4000`. The initial API check is `GET /api/health`.

For deployment-style startup, run `npm run build` in `frontend` and `npm start` in `backend`.

## Installed packages

- Frontend: React, React DOM, Vite, the Vite React plugin, and Oxlint.
- Backend: Express, `pg`, `jsonwebtoken`, `bcrypt`, `dotenv`, `cors`, and Nodemon for development.

Database credentials and the JWT signing secret belong in `backend/.env`, which is ignored by Git. Use a Supabase PostgreSQL connection string for `DATABASE_URL`; Supabase Auth is intentionally excluded.
